- **2026-10-02 16:10** Read the official evaluators. Findings that shape the harness: (a) ATE for the controlled set is evo Umeyama with scale, timestamps matched at 1 ms, and the estimate must span at least half the ground-truth duration or it is rejected; (b) pose recall is computed in 2D (xy only) after the control-point Sim3 alignment, over all pseudo-GT keyframes, so any missing pose is a miss; (c) only `imu-right` (the 1 kHz IMU) is used; (d) pseudo-GT poses are in the left-camera frame, submissions for IMU methods are `world_from_imu`.

Decision: start with ASL/pinhole for the baseline; the fisheye-vs-pinhole question becomes a later experiment needing a separate `.vrs` download.

- **2026-10-02 17:30** Two harness fixes before the first run: (1) OpenVINS stereo KLT needs equal image sizes, and the LaMAria pinhole images differ (758x572 vs 757x569); the runner now pads the smaller image bottom/right and masks the padding, intrinsics untouched. (2) The static initializer never triggers on head-worn data: image disparity is above 10 px even in the first seconds, so the "still" state is never detected. Enabled OpenVINS dynamic initialisation (`init_dyn_use: true`); it initialises 2.3 s into R_01_easy. Decision: dynamic init is part of the baseline, since the robot must also start while moving.
- **2026-10-02 18:00** First numbers. R_01_easy: ATE 0.169 m (sim3 scale 0.993), poses for every image, 60 s wall for 145 s. R_04_medium: diverged (ATE 41.7 m, sim3 scale 0.0018), speed already 2.2 m/s in the first 10 s, accelerometer bias runs to 3.5 m/s^2, online camera-IMU offset jumps to -15.6 ms at init. Decision: before calling anything "the baseline", test online time-offset calibration off and IMU noise x10 (and both) on R_04_medium, run in parallel as `configs/explore_*`; record all attempts in experiment 001.
- **2026-10-02 18:30** Exploration on R_04_medium (single runs): time-offset calibration off gives ATE 1.63 m, IMU noise x10 gives 1.11 m, both together 7.75 m. Repeating two of these with identical input reproduces the positions exactly, so OpenVINS is deterministic on this harness and the non-monotonic numbers are real sensitivity, not randomness. Noise x10 hurts R_01_easy (0.169 to 0.492 m, scale 0.96). Hypothesis: x10 also inflates the bias random walks, which the calibration file already sets high (acc walk 6.4e-3). Added a separate `--walk-scale` and started density-only x10 variants plus offset-off on R_01.
